# Triage Queue Management

## Overview
Triage is a state machine, not a mood. The agent engages the queue, not just the individual work item.

## Canonical roles

Each issue should have:

- Category role: `bug` or `enhancement` (or project equivalent).
- State role exactly one of:
  - `needs-triage`
  - `needs-info`
  - `ready-for-agent`
  - `ready-for-human`
  - `wontfix`

Project labels may differ, but the role mapping must be explicit.

## AI comment prefix

Every AI-authored issue comment must begin:

```markdown
> *This was generated by AI during triage.*
```

No exceptions. Readers deserve provenance.

## Triage flow

1. Gather: read issue, comments, linked PRs, project glossary, prior out-of-scope ledger.
2. Detect label conflicts before any other action.
3. If bug: reproduce before grilling the reporter when possible.
4. If enhancement: compare with `.out-of-scope/` prior rejections.
5. Recommend next state with evidence.
6. Before applying labels, output the current role mapping and proposed transition: `[current state] -> [next state] because [evidence]`.
7. Ask only the smallest needed question, with recommended answer if applicable.
8. Apply labels/comments only when allowed.

Mutating issue trackers requires explicit permission, exact issue URL/ID, and a dry-run summary first. Distinguish "recommend label" from "apply label".

## Out-of-scope ledger

When rejecting recurring enhancement classes, write durable records:

```markdown
# [Rejected idea]

Date: YYYY-MM-DD
Decision: wontfix / out of scope
Reason: [specific tradeoff]
Applies to:
- [future requests this should catch]
```

Store under `.out-of-scope/` or the project's equivalent.

## Anti-rationalization table

| Rationalization | Correction |
|---|---|
| "This issue is obviously a bug." | Reproduce or cite evidence first. |
| "Labels are just metadata." | State conflicts cause wrong work. Fix them first. |
| "AI prefix is noisy." | Provenance is non-negotiable. |
| "We've rejected this before somewhere." | Link the ledger entry or create one. |

## Verification checklist

- [ ] Role mapping known.
- [ ] State-role conflicts checked.
- [ ] Bugs reproduced or reproduction attempt documented.
- [ ] AI comments prefixed.
- [ ] Wontfix/enhancement decisions recorded in ledger.
